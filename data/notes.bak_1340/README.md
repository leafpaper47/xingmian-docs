# 插件人工注解库（notes）

`gen_docs.py` 在生成每个插件页时，会读 `data/notes/<slug>.json`（slug = 插件名小写、非字母数字转 `-`）。
**有注解 → 生成完整版页面（定位/场景/流程/指令详解/坑）；没有注解 → 退回 plugin.yml 的极简页面。**
所以补齐注解是「完善插件指令功能与用法」的唯一入口。

## 硬规则

1. `name` 必须与 `plugin_commands.json` 里的 `name` 完全一致。
2. `commands[].cmd` 必须出现在该插件真实指令列表里（不能编造指令）。
3. 子指令写进 `subcommands[]`（`/lp` 那种「一个主指令 + 几十个子指令」的插件，重点在这里）。
4. 示例一律以 `/` 开头，用真实语法；不确定的参数不要编，写清楚「以 `/x help` 为准」。
5. 纯文本，不要 markdown 表格/代码围栏；不要出现 `{{ }}`、裸 `< >`（会被 Vue 模板吃掉）。
6. 说人话：写给「刚接手服务器的管理员」看，而不是写给插件作者看。

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 插件名，与数据源一致 |
| `role` | ✅ | 一句话定位，≤ 30 字，例：「全局权限系统：组/玩家/权限节点」 |
| `summary` | ✅ | 2–4 句：这插件解决什么问题、和哪些插件配合 |
| `whatFor` | ✅ | 2–6 条「什么时候会用到它」，每条一个具体场景 |
| `flow` | 建议 | 3–5 步上手流程（先干什么、再干什么） |
| `commands` | ✅ | 每条真实指令一个对象，见下 |
| `subcommands` | 建议 | 子指令速查，`{cmd, desc, example}` |
| `caution` | 建议 | 2–5 条坑/注意事项（回滚、覆盖、重启、权限继承…） |
| `related` | 可选 | 相关插件名数组 |

`commands[]` 对象：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `cmd` | ✅ | 指令名（不带 `/`），必须是真实指令 |
| `what` | ✅ | 这条指令干什么，一句话，≤ 40 字 |
| `syntax` | 可选 | 真实语法，例 `/lp <子指令> [参数]` |
| `params` | 可选 | `[{name, required, note}]`，解释每个参数 |
| `examples` | 建议 | 1–4 条真实示例 |
| `notes` | 可选 | 补充说明/坑 |

## 参考样例

`luckperms.json`（单主指令 + 大量子指令）与 `coreprotect.json`（回滚类，重流程与风险）是两种典型写法，照着学。
