# 背包快照 · InvSaver

> 分类 🧰 基础工具 · 版本 `1.0.1` · 指令 1 条 · api-version `1.20`

::: tip 背包快照保存与回滚工具
把玩家当下的背包整体存成一份快照，需要时再回滚回去，用来兜住误清包、误操作、异常物品这类不可逆事故。它不参与日常游戏玩法，主要给服主和管理员做运维兜底，通常和权限插件、查号/封禁流程、活动发奖流程配合使用。
:::

## 什么时候会用到它

- 活动、发奖、批量调背包之前，先给关键玩家存一份快照，事后可回退
- 玩家申诉物品丢失或被误清包时，用快照核对并恢复原状
- 处罚、查号前先备份现场，保留玩家背包的实际内容作为证据
- 怀疑刷物品或出现异常物品时，先保存再处理，避免证据被覆盖

## 上手流程

1. 先确认权限：保存、恢复、列表、预览、重载是五个独立节点，按需分配给管理组
2. 在主指令下找到对应子功能，对目标玩家执行保存，得到一份快照
3. 恢复之前先用预览和列表核对快照内容，确认是要回滚的那一份
4. 真要恢复时，先给玩家当前背包再存一份，然后才执行恢复
5. 改过配置文件后用重载功能生效，不必重启服务器

## 指令详解

### `/invSaver` — 背包快照主命令，包含保存、恢复、列表、预览、重载等功能

- **语法**：`/invSaver`

- **示例**：

```
/invSaver
```

- **备注**：输入数据只给出主命令，未提供子指令与参数格式，具体写法请以游戏内帮助输出为准。五个权限节点 invSaver.reload、invSaver.save、invSaver.restore、invSaver.list、invSaver.preview 分别对应重载、保存、恢复、列表、预览，默认只有 OP 拥有。

## 注意事项

::: warning
- 具体参数与子指令以游戏内 help 为准，本文只列出已确认的主指令和权限节点，未确认的写法不要照抄
- 恢复会直接覆盖玩家当前背包，执行前一定要先预览核对，并给现背包再存一份，否则可能造成二次损失
- 五个权限节点默认仅 OP 可用，下放给普通管理组时只给需要的那一个，尤其恢复权限要谨慎
- 快照只反映保存那一刻的状态，保存之后的物品变动不会同步，长期问题不要指望用旧快照解决
:::
