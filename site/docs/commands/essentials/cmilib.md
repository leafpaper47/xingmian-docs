# CMI前置库 · CMILib

> 分类 🧰 基础工具 · 版本 `1.5.9.9` · 指令 1 条 · api-version `1.13`

::: tip CMI 等插件的前置依赖库，本身不提供玩法
CMILib 是 CMI 作者发布的公共代码库，把物品序列化、版本比对、粒子与实体处理等通用功能打包成一份，供 CMI 和其它同作者插件调用。它自己不面向玩家，装好后基本不用配置，删掉它依赖它的插件就会直接报错或无法启用。管理员通常只在安装或升级 CMI 时和它打交道。
:::

## 什么时候会用到它

- 安装或升级 CMI 时，作为必须先放好的前置库一起丢进 plugins 目录
- CMI 启动报缺少 CMILib、类找不到或版本不匹配时，用来确认库是否在位、版本是否够新
- 排查多个插件互相冲突时，确认它们共用的是同一份 CMILib 而不是各自带的旧副本

## 上手流程

1. 把 CMILib 的 jar 放进服务端 plugins 目录，和 CMI 一起放，顺序无所谓
2. 启动服务端，看控制台里 CMILib 是否显示已启用、版本号是多少
3. 再确认 CMI 也正常启用没有报错，才算这一步过关
4. 以后升级 CMI 时同步检查 CMILib 版本，必要时一起换新

## 指令详解

### `/cmil` — 库自身的基础指令，一般只用来查看信息，日常几乎用不到

- **语法**：`/cmil`

- **示例**：

```
/cmil
```

- **备注**：这条指令属于维护性质，没有面向玩家的玩法功能；不确定具体子参数时以游戏内输入 /cmil 后弹出的提示为准，不要凭猜测乱敲参数。

## 注意事项

::: warning
- CMILib 是前置库，不能单独卸载或停用，删了 CMI 之类的插件会直接起不来
- 一个服务端只保留一份 CMILib，不要出现两个版本并存，否则容易出现版本冲突
- 升级 CMI 后如果报库版本过低，先把 CMILib 换成配套的新版本再启动
- 具体参数与子指令以游戏内 help 或输入 /cmil 后的提示为准，不要照抄网上的旧教程
:::
